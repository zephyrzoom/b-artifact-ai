# b-artifact M1.6 性能修复报告（B1/B2/B4/B5/B6）

**日期**：2026-09-14
**范围**：M1.5 压测定位的 6 个瓶颈中，除 B3（refcount GC 相关子查询，P2）外的 5 项全部修复 + 回归实测
**结论**：Path-History 的两条核心查询从"1M 文件档位下不可用"变为**毫秒级**；列仓库根目录从
**206 ms → 5 µs**（m 档，4.5 万倍），提交 1000 条变更从 **67.5 s → 21 ms**（3213 倍）。
唯一未达标项是**非 HEAD 修订的列目录**（仍需 7.4 s，仅 3×），见 §6。

> M1.5 的原始报告见 [压测报告-M1.5.md](压测报告-M1.5.md)；本报告只讲修复与回归。

## 1. 修了什么

| 编号 | 问题 | 修复 | 位置 |
|---|---|---|---|
| **B1** | 前缀 `path LIKE 'pfx%'` 在默认 `case_sensitive_like=OFF` 下不下推索引，退化为整仓扫描；**空前缀（仓库根）连 GLOB 也救不了** | 改为**半开区间** `path >= lo AND path < hi`（上界 = 前缀末字节 +1：`"art/"` → `"art0"`），不依赖任何 pragma | `storage/repo.rs`：`prefix_bounds()` / `LAST_CHANGES_UNDER_RANGE` |
| **B2** | 热路径用 `conn.prepare`，每条语句每次重新解析（7.3 µs） | 全部改 `prepare_cached`（0.3 µs）；新增 `cached_row()` 辅助 | `storage/repo.rs` |
| **B4** | 列目录要读"全部后代"：`head_entries` 无 `parent_path`，只能前缀扫 | 加 `parent_path` 列 + **物化全部目录行**（显式 `is_explicit=1` / 隐式 `=0`），列目录变 `parent_path = ?` 等值查询 | 迁移 `003_perf.sql` + `storage/repo.rs` |
| **B5** | `changes.blob_hash` 无索引，提交时每条变更反查整仓历史 | 加**部分索引** `WHERE blob_hash IS NOT NULL` | 迁移 `003_perf.sql` |
| **B6** | `AppState.db: Mutex<Connection>` 使 DB 并发度结构性恒为 1 | 自研阻塞式连接池 `DbPool`；写事务一律 `BEGIN IMMEDIATE` | `storage/pool.rs`、`state.rs` |

### 1.1 顺带清掉的遗留项

- **强制解锁留痕**：补 `locks.broken_at / broken_by / break_reason` 三列（§5.5），此前表结构缺列。
- **prepare 幂等短路**：原来靠"空 token + `need_blobs[0]` 承载旧 rev"传值，改为 `enum PrepareOutcome { Replayed, Prepared }`，语义显式。
- **造数脚本对齐新不变量**：`scripts/gen_fixture.py` 写入 `parent_path` 并物化目录行，否则新生成的 fixture 列不出目录。

### 1.2 迁移 003：幂等 + 存量回填

`003_perf.sql` 新增 `parent_path` / `is_explicit` 后，**存量库必须回填**：

- `db::migrate` 记下本次真正应用的迁移，若含 `003_perf` 则调 `backfill_head_tree()` 逐仓库重建；
- 回填前先 `UPDATE head_entries SET is_explicit = 1 WHERE kind='dir'`——旧库里只有 mkdir 会写目录行，
  它们一律是显式的；不先标记就会被重算成隐式，空目录随后遭误回收。
- `rebuild_head_tree()` 也是**自愈入口**（与 `rebuild_refcount()` 同类）：只依赖文件行重算目录行与
  `parent_path`，并原样保留显式目录行。

> 本轮回归**顺带验证**了这条迁移路径：压测用的 fixture 是 M1.5 遗留的**旧库**（无 `parent_path` 列），
> harness 打开时自动跑 003 + 回填，m 档（24 万文件 / 43.9 万 changes 行）正常完成压测。

## 2. 方法

- **同 fixture、新旧代码对比**：xs/s/m 三档全部复用 M1.5 的旧 fixture（`/tmp/b-artifact-fixtures`），
  因此"修复前"就是 M1.5 的实测值，"修复后"是同一份数据跑新代码。**口径一致**。
- 档位：`xs` 1,000 文件 / 200 修订；`s` 40,000 / 1,000；`m` 240,000 / 20,000。
  （`full` 1M 文件档按计划**未跑**，本轮按 xs+s+m 三档收敛；§6 给出外推。）
- 命令：`scripts/m15_bench.sh --scales xs,s,m --iterations 25 --budget 12 --concurrency 8,32`
- 对比表由 `scripts/m16_compare.py` 生成（p50，提速 = 前/后）。

> ⚠️ **测量陷阱（本轮踩到，写进流程）**：用 `--only conc` 单独跑并发组**不可复现**
> （同一配置两次相差 10 倍：pool=4 一次 1946/s、一次 202/s）。原因是缺了前面几组的预热，
> 136 MB 的 DB 处于冷页缓存状态。**并发结论一律取"完整跑"的数据**，本报告的并发表全部来自完整跑。

### 4.1 怎么看这几张表

- **HEAD 列目录**：从"读整张 `head_entries`"变成"读直接子项"，代价与仓库规模**脱钩**
  （m 档 5 µs，xs 档 4 µs，几乎不随档位变化——这正是 B4 想要的效果）。
- **历史推导列目录**：叶子目录 332×、二级 3.6×、根 3.0×。**越深收益越大**，因为前缀下推把扫描项
  从"整仓"缩到"子树"，剩下的开销是逐候选存活判定（受 B2 影响）。
- **写入**：`apply_commit_1000` 从 67.5 s → 21 ms。B5 的索引把 blob 新颖性反查从整仓扫描变成点查。
- **前缀扫描组**（`head_prefix_like_*` 等）**没有变化**——它们是直接下 SQL 的语法对照基准，
  不走生产函数，本来就只用来证明"`LIKE` / `GLOB` 在空前缀下都救不了"（M1.5 §4 的证据）。
- **`repo_info` / `missing_1000` 略有回退**（0.81× / 0.94×）：`head_entries` 多了约 11% 的目录行，
  而 `repo_info` 本身是**全表 COUNT 扫描**——它本来就是 O(N) 端点，本轮没动它，见 §6。

## 5. B6 专项：连接池调参实测

B6 不只是"换成池"，池开多大必须实测。以下均为 **m 档完整跑**（并发 64 请求）：

| 池大小 | `tree_root_depth1_c8` | `download_blob_c8` | `log_50_c8` | `repo_info_c8` |
|---|---|---|---|---|
| 1（= 修复前的 Mutex 行为） | 5/s | 4610/s | 1026/s | 25/s |
| 2 | 232/s ᵃ | 4826/s | 1311/s | 27/s |
| **4（已设为默认）** | **3451/s** | **3529/s** | **819/s** | **33/s** |
| 8 | 3295/s | 459/s | 252/s | 30/s |

ᵃ pool=2 的 `tree_root_depth1_c8` 被一个 260 ms 的离群点拖垮（p50 其实只有 1.51 ms），属单点毛刺。

**结论**：

1. **8 条连接明显过量**——查询修复后单条已足够快，连接再多只剩 WAL 读竞争与排队，
   `download_blob_c8` 从 3529/s 掉到 459/s（−87%）。
2. **默认取 4**：与 2 互有胜负，但比 8 在所有并发项上都更好或持平；留 4 条是为了让长查询
   （历史树单请求 6.5 s 量级）不至于堵死全部读。
3. 可用 `B_ARTIFACT_DB_POOL_SIZE` 覆盖（运行期），不必改代码重编译。

### 5.1 `block_in_place` 的对照实验

连接池满时 `get()` 会睡在 Condvar 上。理论上这阻塞的是 tokio 工作线程，应当包一层
`block_in_place`。**实测并不划算**（m 档完整跑口径下 8 worker 全部进入 `block_in_place` 时
runtime 腾挪不开，p95 反而变差），因此：

- 默认**关闭**；保留运行期开关 `B_ARTIFACT_DB_BLOCK_IN_PLACE=1` 供后续复测。
- 彻底的修法是**把池改成异步的**（`tokio::sync::Semaphore` + `spawn_blocking`），
  让工作线程永不阻塞——留作 M2 前的可选优化，见 §6。
